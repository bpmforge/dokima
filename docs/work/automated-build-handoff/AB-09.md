## Do these steps in order

1. Add the normalized Finding record described in IMPLEMENTATION_PLAN.md. Preserve original tool/reviewer records and origin ids.
2. Deduplicate exact findings by check/rule, normalized relative path, location and evidence fingerprint. Retain all origins. Do not merge unrelated vulnerabilities because titles sound similar.
3. Group open findings by owning ticket/write scope. A repair outside approved scope becomes an explicit scoped proposal, not a silent scope extension.
4. Include required verification check ids in the repair batch. Model-suggested commands are suggestions; trusted runtime chooses executable checks.
5. Keep unverified specialist hypotheses distinguishable from confirmed tool defects. Consolidation must not promote a hypothesis to proven defect or erase it silently.

## Acceptance — all must hold

- [ ] Two identical tool findings produce one repair with two origins.
- [ ] Similar titles at different paths/locations remain separate.
- [ ] Out-of-scope repair is parked with evidence; invalid paths and missing verification cannot pass normalization.
