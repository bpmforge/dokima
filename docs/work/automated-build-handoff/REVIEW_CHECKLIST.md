# Independent completion review

Review the implementation and execution evidence, not the maker's summary alone.

- [ ] Actual start route and CLI enforce the same approved input snapshot.
- [ ] Existing auto users are not silently opted into new behavior.
- [ ] Reviewer sees actual bounded diff/source and independent checks.
- [ ] Named scanner actually executes; model text cannot mint its result.
- [ ] Missing tool/network/reviewer is explicit, not a pass.
- [ ] Shared endpoint pool covers coding, analysis and review.
- [ ] Grouped tasks obey dependencies, write scopes and bounded resources.
- [ ] Failed upstream retry invalidates downstream evidence.
- [ ] Repair is a real reject/reclaim/fix/verify cycle with durable limits.
- [ ] Fresh independent machine acceptance unlocks dependent work.
- [ ] Main/master and publication remain separately gated.
- [ ] Same checks hold for one berth and multiple berths.
- [ ] Acceptance cannot use stale source, stale receipt or stale reviewer verdict.
- [ ] Stop, crash, restart and duplicate start retain truthful state.
- [ ] Combined preview is verified, not merely each ticket independently.
- [ ] UI component is mounted and calls the real production route.
- [ ] Full required gates pass; new critical scenarios pass without retries.
- [ ] Tests use fake providers; live proof is labeled separately.
- [ ] No edits to signed content, weakened ratchets, broad cleanup or hidden fallback.
- [ ] Findings outside scope have actual ticket ids.

A separate reviewer should attempt to refute the evidence at the repository's required wave gate. Record commands re-run independently. Failed or unverifiable criteria remain open.
