## Do these steps in order

1. Move the existing SHARED_GATEWAY_POOL ownership into one shared composition module. Import that same instance in coding, review and onboard dispatch paths. Do not construct one pool per call.
2. Normalize endpoint identity so two role/provider aliases targeting one endpoint share a limit. Keep secrets out of keys. Test trailing slash/base URL normalization explicitly.
3. Default to one active model request per endpoint. Permit a validated explicit limit for capable endpoints; do not assume all cloud endpoints accept unlimited work.
4. Preserve existing adapter queues and rate-limit handling. Avoid acquiring the same non-reentrant pool twice for one request; one outer pool acquisition per real request.
5. Keep CPU scanner concurrency separate. Check that stop/timeout releases slots and that errors cannot leak active counts. If shared scheduler lacks cancellation, add it with a regression before relying on immediate cancellation.

## Acceptance — all must hold

- [ ] Two roles sharing an endpoint never exceed one default active request even if providers are constructed separately.
- [ ] Two distinct endpoints can overlap; failed/cancelled requests do not wedge the pool.
- [ ] Coding, review and onboard production call paths all use the shared pool.
