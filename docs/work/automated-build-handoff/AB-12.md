## Do these steps in order

1. Inject one post-close verify/review/repair/accept operation into the common one-ticket engine used by both sequential and berth execution. Do not wait until executeBuildRun returns to review required predecessor work.
2. On a fresh eligible decision and opted-in approved policy, call the existing acceptTicket under the real reviewer identity. Validate the current receipt and head immediately before acceptance. Inconclusive decisions stay in_review.
3. After acceptance let existing reflow discover newly ready dependents. Keep depsDone requiring done; never treat in_review as accepted to make a demo finish.
4. Build dependents from existing accepted-dependency base composition. Main/master merge remains a separate decision. Fix an integration conflict on an isolated composed branch only within approved scope.
