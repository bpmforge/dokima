## Do these steps in order

1. Expose a one-ticket review operation; retain runReviewPass as a compatibility wrapper. Allow selecting current-run ticket ids so old in_review tickets are not reprocessed by accident.
2. Return a structured decision containing reviewed head/input digest, independent check statuses, normalized findings and model/identity provenance. Keep existing human-readable verdict events compatible.
3. Independent check failure dominates the verdict. Parse failure, same maker model, missing reviewer, truncated evidence and unavailable required scan are inconclusive, never automated success.
4. Use a genuine dedicated reviewer machine identity minted by the runtime. Do not attribute machine review/acceptance to the human who started the build. Keep makerModels refusal across every rung.
5. For independent specialist reviews over a fixed snapshot, call the common scheduler. Keep one final consolidated decision after all required results arrive.

## Acceptance — all must hold

- [ ] Maker identity/model cannot review its own work, including maker models used during escalation.
- [ ] A fresh complete review returns an eligible decision; every unavailable/stale/inconclusive condition returns an ineligible one.
- [ ] Current-run selection does not review unrelated parked tickets.
