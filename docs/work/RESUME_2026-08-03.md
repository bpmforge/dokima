## 4. The five findings worth remembering

These are the ones that changed how the codebase is verified, not just what it
contains.

1. **A green suite is not evidence a surface works.** Every ticket drawer fired
   `GET /api/v1/api/v1/…/receipts` and 404'd, rendering a raw *"Artifact API
   request failed with status 404"* to the user. 2,923 unit tests and 59 e2e
   specs passed throughout, because `EvidencePanel.test.tsx` never asserted a
   URL and `CommandPalette.tsx` had no test file at all. Found by recording
   console errors per screenshot (W10-29).

2. **A gate can be blind to absence.** W10-06's design gate fails on a hex
   literal that is *present*; it could never see a colour that is **never
   declared**. Anchors had no colour rule anywhere in `apps/web` and fell back
   to the UA default at **1.95:1** in dark — a seventh AA failure, invisible to
   the mechanism that found the other six. The fix was the gate (W10-30).

3. **A layout constant was calibrated against a bug.** `.sr-only` was applied
   in five components and defined in zero stylesheets, so "Move ticket E2E-1"
   painted as visible copy. `board.css` recorded that this same text was why
   the column floor was raised to 9rem. Defining the class let the floor drop
   to 8.5rem and reclaimed a third board column (W10-32).

4. **A fixture taught a false contract to everything above it.**
   `seed-tour-trace.mjs` invented two payload keys — `payload.validators` on
   gate events and `payload.reason` on escalation events — that no production
   appender writes. The visual audit read the fixture, concluded the data
   existed, a ticket demanded it be surfaced, and an agent implemented it
   before review caught it. `docs/TESTING.md` now records: **a fixture may
   record less than production, never more** (W10-41).

5. **The verification harness itself lied once.** `ensureSpaBuilt()` skipped
   the build whenever `dist/index.html` merely existed, so a capture run served
   a bundle from an earlier commit and reported a working fix as broken. It now
   rebuilds unconditionally. `capture-tour.mjs` and `capture-acceptance.mjs`
   both depend on it, so `docs/tour/` was only ever as trustworthy as that
   check (W10-37).

**The design gate now covers a progression, each rung added because something
real slipped past the previous one:** no raw hex → no raw px → no *missing*
declaration → no applied-but-undefined class → no off-scale rem. Each rung
ships with self-tests proving it can fail.

## 5. Traps

Traps 1–6 from [`RESUME_2026-08-02.md`](RESUME_2026-08-02.md) all still apply —
**Node 22 only**, the signing key at `~/.shipwright/keys/`, zsh not
word-splitting, `pnpm test` not being the whole gate, the force-push hook, and
mutation testing needing the right subject. New ones from this session:

1. **`validate-plan.mjs` is a conductor gate.** An invalid board on `main`
   fails the gate of **every subsequent ticket** and can halt an overnight run.

2. **Gate on its exit code — printing it is not gating.** Two invalid boards
   reached both remotes on 2026-08-03 from the same mistake in two disguises:
   `validate-plan.mjs | tail -3 && git push` (a pipe's exit status is the last
   command's) and `validate-plan.mjs; echo $?; git commit && git push` (the `;`
   pushes regardless). The only safe shape:
   ```sh
   if node scripts/validate-plan.mjs >/dev/null 2>&1; then git commit … && git push …; fi
   ```

3. **`plan.json` schema is strict.** `acceptance` is capped at 6 entries (P5);
   `module`/`lane` come from fixed sets at `validate-plan.mjs:29-30` — **there
   is no `server` value** (apps/server route work is `module: gateway` or
   `module: web`); `points` ∈ {1,2,3,5,8}. Always write it through
   `writePlan()` from `scripts/conductor-lib.mjs` — the file is ASCII-escaped
   and a bare `JSON.stringify` rewrites 460 lines and reds a W9-11 test.

4. **A board edit made mid-flight does not reach the running ticket.** The
   conductor caches the ticket at claim time. Correct the board, let it block,
   then reset to `todo`.

5. **A file split invalidates the `write_scope` of every pending ticket naming
   it.** W10-39 passed its own gate perfectly and still broke queued W10-33.
   Sweep the board when a split lands.

6. **The conductor can report "nothing claimable" spuriously.**
   `claimableTickets` filters on `busyLanes`; if the just-finished ticket shares
   a lane with the remaining ones it can idle with work left. A clean restart
   fixes it. Happened twice.

7. **Never stop the conductor by process name.** `scripts/conductor.mjs` is a
   vendorable template — other repos on this machine run their own copy under
   the same filename, so **`pkill -f conductor.mjs` reaches beyond this
   project** (proven the hard way on 2026-08-03). Kill only descendants of the
   supervisor PID that `pnpm autorun` printed. If you must identify a live run,
   its board path is the tell: Dokima's is `plan.json` at the repo root, a
   vendored copy points `boardPath` somewhere else.

8. **Retry budget is 2 without `--escalate`.** A mechanical slip (e.g.
   forgetting to set `status: done`) consumes a full attempt, leaving only one
   for substantive review feedback.

## 9. A note on filing tickets

Six of the fifteen tickets filed this session had scope defects, all one habit:
**writing acceptance criteria that describe behaviour, then setting
`write_scope` from whichever file came to mind.** Every one was caught
downstream — by the validator, by an agent refusing to work around a bad scope,
or by a reviewer — but each cost a session.

Before filing: grep the behaviour each criterion describes, scope the file that
**actually contains it** plus its test sibling, and check contention against
non-done tickets. Makers will not self-widen (W8-06 precedent: rejected as
illegitimate self-authorization), so an under-scoped ticket reliably costs a
full agent session and a self-block.

The corollary is worth keeping: **the agents' self-blocks were consistently
high-quality** — exhaustive grep evidence, contention already checked, and a
concrete scope-amendment recipe. Two of them were correct that my ticket was
wrong; one was itself wrong about the codebase (it blocked on a barrel export
that already existed, misled by a stale comment). Verify a block's claims
before acting on them, in both directions.
