> **Status 2026-09-14 (same day):** defects 2, 3 and 4 fixed on
> `fix/ux-review-defects` and verified (scrollWidth 375 at 375px on Fleet,
> wizard, settings, roster; gutters present on desktop). Defect 1 was a
> **review-harness artifact**, not a product defect: the capture ran against
> the vite dev server on :4318, which has no injected bearer token. Through the
> core on :4317 (which injects `~/.dokima/token` into `index.html`), Fleet
> renders three projects with no error. Defect 5 (settings copy length) left as
> filed.

Method: server via `cli-entry.mjs` (packaged bundle of 2026-09-03, 45 commits stale —
API shape only), web from source on :4318. Captured Fleet, wizard, settings, roster,
notifications, plans at 1440px and 375px with Playwright; probed overflow + console.
No code changed by this review.

## Verdict

Honest, text-forward, zero-chrome. Copy is excellent. Visually it is unfinished:
no page gutters on several panes, a header that breaks at phone width, and a first
run that shows red error text before the user has done anything.

## End-user (persona: founder trying it for the first time) observations

- The wizard's first question is genuinely good: five plain-language model policies with cost consequences spelled out. Keep this.
- No visual hierarchy between the app header and the pane header (both white, both 60px). Use a background tint or border on the pane header.
- Light/Dark toggle exists and is labelled. Good. Verify the dark palette on the same screens (not captured here).
- Radio options in the wizard lack hit-area padding; the whole row should be clickable.
- No loading state anywhere; text appears, then the error appears.

## Against 2026 trends

1. **Dark-first developer tools with elevation by lightness.** Dokima already has a toggle; consider dark as the default for a tool that watches builds overnight.
2. **Agent-build products show the plan, the running step and evidence side by side** (Cursor, Devin, Claude Code web). Dokima has board/trace/decisions views; the Fleet home should preview "what is running now" the way Jarvis's banner does.
3. **Systematic spacing + a real type scale.** Current pages use one body size and one heading size with no container rhythm; adopt an 8pt grid and a max-width container on every view.
4. **Skeletons and entrance motion are table stakes.**
5. **Bento-style asymmetric grid for the Fleet page** once projects exist: status tile, next action, recent decisions.
