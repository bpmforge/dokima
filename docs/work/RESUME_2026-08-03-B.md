## 3. The one finding that matters most

**Everything real this session was found by running the product, not by reading
it or trusting the suite.** Five defects, every one under a fully green gate:

1. **The shipped validator pack could not run at all** (W10-52). `_lib*.sh` were
   absent from the signed manifest, so a real install landed 81 validators and
   zero shared libraries; executing any one exited **127**. 3,147 tests passed
   throughout, because the repo runs validators from the source tree where the
   libraries sit beside them.
2. **`New Product` was a dead end** (W10-54). A created product had *no control
   that started anything*. The only code path calling `pipeline/run` was the
   guided sample, on a hardcoded idea. The README's core promise had no entry
   point.
3. **The guided sample produced zero durable state** (W10-55). Completed every
   beat: 0 events, 0 receipts, no tickets table, the model never called, the
   server logged nothing — while its copy claims it "runs the whole lifecycle on
   your configured model".
4. **The published package could not find its own assets** (W10-43). Scoping the
   name for npm broke a distribution-root probe that matched a hardcoded package
   name. `npm pack --dry-run` listed a perfect 240-file tarball and told me
   nothing.
5. **A 60s provider timeout made local models unusable** (W10-57), and raising it
   to 300s was still not enough — see §5.

The shape is always the same: **the missing assertion is "and then it actually
worked."** Counting files, verifying signatures, listing a tarball, and passing
3,000 tests are all compatible with a completely broken artifact.

> **If you do one thing differently: drive the installed package, in a browser,
> as a user.** `npm pack` → install into a clean dir → run the binary → click
> through it. Every finding above came from that and none came from the suite.

## 4. Traps

Traps 1–8 in [`RESUME_2026-08-03.md`](RESUME_2026-08-03.md) still apply. New:

1. **`--manifest-only` WRITES.** `scripts/import-content.mjs --manifest-only`
   regenerates `content/index.json` on disk. It is not a read-only inspection;
   it dirtied a file outside a ticket's `write_scope` during verification.
   `--dry-run` is the safe one.
2. **Re-sign AFTER the last content edit, not before.** Editing any signed file
   after `sign-content.mjs` invalidates the manifest. Caught only by
   `packs-update`'s real-pack verification, never by inspection.
3. **The repo-wide file-size gate is live** (W10-49). A new file over 400 lines
   now fails *its own* ticket. It caught two of mine within an hour. That is
   working as designed — split rather than argue with it.
4. **`validators.repoWide` is only honest at a ZERO count.** If
   `validate-file-size` ever goes non-zero repo-wide, every ticket fails for debt
   it did not create. Remove the entry rather than waive it; a test asserts the
   precondition.
5. **The design gate catches invented token names.** `--sw-text-muted`,
   `--sw-surface-2` and `--sw-text` do not exist; the real ones are
   `--sw-fg-muted`, `--sw-bg`, `--sw-fg`. Check `styles.css` before writing CSS.
6. **Backticks and apostrophes in ticket text.** Filing tickets via
   `node --input-type=module -e "…"` in a shell gets mangled by shell
   substitution — one acceptance criterion silently lost its path names. Write
   the filing script to a file and run it, never inline.

### W10-58 is the last structural blocker

Measured, not inferred: one pipeline-sized call to `qwen3.5-9b` on this hardware
takes **33 seconds and 3,088 completion tokens, 2,987 of them reasoning**. The
pipeline issues several sequentially over growing prompts, so it exceeded 300s.

**There is no timeout constant that is both large enough for a local reasoning
model and small enough to still mean "something is wrong."** The synchronous
shape is the defect. Make it a job: return a run id immediately, append phase
events as they complete, persist partial progress so a slow box can finish
across attempts. The event log and WebSocket transport already exist and already
carry board updates — this is wiring an existing spine.
