## Findings, ranked by how badly a first-time user gets lost

### A-1 · Roster is a debug dump wearing a nav tab (worst)

Every expert card prints its full internal system-prompt description —
"checks all 31 ANTI_SLOP_RULES (R-01 to R-31)… GitClear, Veracode, CSA, and
USENIX 2025 research plus a field-lesson intake (B-2)" — text written for a
model, shown to a person. Every card then stacks three failure-toned lines:
*"unconfigured — no routing matrix entry"*, *"not benched"*,
*"instruction cost: —"*. A user reads a wall of "unconfigured" as **your
product is broken**, when nothing actually needs configuring — roles resolve
through the default matrix. And "routing matrix entry" violates VOCABULARY.md
on its own screen (the user-facing word is **Models**). The screen offers no
action of any kind. It answers "what is this?" for the builder and nothing for
the user.

### A-2 · Plan presents the user's own features as "findings"

The user described a product; the Plan screen shows their 8 features as
"8 raw findings → 8 plan items → 8 accepted → 0 done / 0 regressed" with
"severity 3 · leverage 3 · priority score 9" on every card. Two problems
stacked: the *funnel vocabulary* is internal machinery (nothing on screen
defines finding/plan item/accepted/regressed), and the *numbers carry zero
information* — identical on every card, so they read as noise with an
authoritative face. Worse, each card shows **two IDs for one thing**
("T001 · Ticket: PLAN-T001") — the exact defect VOCABULARY.md exists to
prevent, on a single card.

### A-3 · The product contradicts its own instructions (vocabulary drift)

Verified by grep, not impression:

- `model-resolution.ts:276` — our freshest error message (W13-34) says
  **"Open Settings → Models"**. The tab is labeled **"Model Matrix"**
  (`SettingsPage.tsx:41`). A user following the product's own instruction
  finds no such tab. VOCABULARY.md already ruled: UI says *Models*.
- `MorningQueue.tsx:275` — quiet-state copy says **"Next digest at wave
  gate."** "Wave gate" is defined nowhere a user can see. The positive-quiet
  message ends on an undefined term.
- Settings has **14 top-level tabs**, at least five named in internal
  vocabulary (Model Matrix, Berths, Suppressions, Rule Lifecycle, Expert
  Overrides). VOCABULARY.md's rule — "the setting is called what it does" —
  applied to the nav would collapse and rename this row.

### A-4 · State is still not carried in form on the board

The direction's core claim: a card that needs you is a different *shape*.
On the board, a Blocked card and a Ready card are pixel-identical except for
which column they sit in. The `.surface--attention` stripe (components.md)
exists and is not applied here. Three smaller comprehension leaks on the same
screen: an unexplained ○ icon on every card; the lane header is a ticket id
("T001") rather than a name; each pane header repeats the word "Focus" with a
« glyph, meaning collapse — three unlabeled controls in a row.

### A-5 · Composition: islands in a void

Fleet (two cards, top-left, ~70% of the viewport empty) and the Morning queue
(one centered card in blackness) both lack the density the instrument-panel
direction promises. The readout signature landed on Fleet cards and works;
the *page* around the cards is not composed. "0:02 elapsed (target 10:00)"
also floats without a label — it is the ten-minute-review budget, but reads
as an unexplained countdown.

### A-6 · Motion: currently forbidden, now requested

VISUAL_DIRECTION.md (founder, W13-03) says **"No motion."** The founder has
now asked for grouping/animation as part of production polish. Per DECISIONS
discipline this is an amendment to record, not a silent violation: the
proposal on the table is a *narrow state-transition policy* — cards animate
only when their state changes (a land, a park, a decision needed), 150–200ms,
`prefers-reduced-motion` respected, nothing ambient. Decide before any ticket
implements motion.

## What is genuinely good (keep, extend)

- The **readout** signature on Fleet cards — value at size, micro-cap label,
  tabular mono. This is the product's best component; A-4/A-5 are largely
  "apply it and its sibling primitives everywhere else".
- The **Providers table** — plain columns, honest "Not tested yet", real
  actions. The best-comprehending screen in Settings.
- The **decision slates** — recommendation marked, trade-offs under each
  option, rationale optional. Comprehension done right.
- The unavailable-project card's honesty ("Nothing on disk is touched").
